# Benchmarking Pretrained Molecular Embedding Models For Molecular Representation Learning

[![arXiv](https://img.shields.io/badge/arXiv-2508.06199-b31b1b.svg)](https://arxiv.org/abs/2508.06199)

---

This is the repository containing the code for the paper "Benchmarking Pretrained Molecular Embedding Models For Molecular Representation Learning" by Mateusz Praski, Jakub Adamczyk, Wojciech Czech. [link](https://arxiv.org/abs/2508.06199)

## Requirements

- Python >= 3.11, < 3.12
- [uv](https://docs.astral.sh/uv/) for the root project environment and for creating per-model virtualenvs

## Installation

Install the root (download + scoring) environment from [`pyproject.toml`](pyproject.toml):

```sh
uv sync
uv run python download.py   # prefer uv run over activating .venv
```

Per-model embedding environments are created automatically by [`embed_wrapper.sh`](embed_wrapper.sh) (via `uv venv`) the first time you run a model wrapper. Each model installs its own dependencies in `model_wrappers/<model>/init.sh`.

## Usage
Start with downloading all of the required datasets. By default, all TDC ADMET + MoleculeNet benchmarks can be downloaded using the command:
```sh
uv run python download.py
```

To run the embedding procedure for an existing model, for all datasets, run the command:
```sh
./embed_wrapper.sh /path/to/implementation # e.g. ./embed_wrapper.sh model_wrappers/huggingface
```

Hydra CLI overrides after the wrapper path are forwarded to `embed.py` (useful for smoke tests):
```sh
./embed_wrapper.sh model_wrappers/huggingface \
  'hydra.sweeper.params.+dataset=glob(clf_ogbg-molbbbp)'
```

If you want to run this in the background, you can use the shorthand command:
```sh
./run_embed.sh <implementation name> # e.g. ./run_embed.sh huggingface
```

This will perform the embedding procedure on all defined datasets (see `config/embed.yaml` for the default list).

To train and evaluate supervised learning heads using the embeddings, run the following command:
```sh
uv run python score.py --multirun +experiment=<implementation name> # e.g +experiment=huggingface
```

If you want to run this in the background, you can use the shorthand command:
```sh
./run_scoring.sh <implementation name> # e.g. ./run_scoring.sh huggingface
```

List of available implementations is defined under `config/experiment`.
List of available datasets is defined under `config/dataset`.

Dataset named `ogbg-molXXX` refers to the `XXX` dataset from the [MoleculeNet](https://moleculenet.org/). The splits are taken from the [Open Graph Benchmark (OGB)](https://ogb.stanford.edu/).

Embeddings will be saved as a [EmbeddedDataset](src/common/types.py) object under `data/embedded/<dataset>/model.<joblib/json>`, depending on the implementation. Due to the Pandas serialization format incompatibility in different environments, we implement a simple custom serialization of outputs from some older models.

SQLite database with the best-performing classifier heads (based on the grid search tuning) will be saved to `data/meta.db`.

In our benchmark study, some of the models required filtering of a small number of SMILES, e.g.: due to the SELFIES translation issues, or lack of support for dative bonds. Those SMILES are defined in [illegal_smiles.txt](config/illegal_smiles.txt) in the config directory. To reproduce those illegal SMILES as in the original articles, please refer to the `selfies_debugger.ipynb` notebook.

## Reproducing the paper's figures and tables

All figures, tables and numbers quoted in the text of the paper (main text and Supporting Information) are generated by [`published_figures/`](published_figures/README.md), from the results stored in [`results/jcim_revision_2026_10/`](results/jcim_revision_2026_10/README.md): the benchmark results database, the external validation results, the embedding times and the dataset statistics. No embedding or scoring has to be rerun.

```sh
uv run --no-sync --with-editable published_figures/bayes-testkit python published_figures/make_figures.py
```

The statistical tests (Bayesian Bradley-Terry model, Bayesian hierarchical correlated t-test) use our [bayes-testkit](https://github.com/MLCIL/bayes-testkit) library. The script takes about 10 minutes and writes the figures and LaTeX tables to `published_figures/output/`, at the paths used by the manuscript, together with `numbers.md`, which lists every number quoted in the text.

The figures of the arXiv preprint (results in `results/arxiv_preprint_2025_08/`) were made with `visualizations.ipynb`.

## CLAMP retraining

The released CLAMP checkpoint was pretrained on PubChem bioassays that contain molecules of the benchmark datasets, so the paper uses CLAMP refitted without them. The [`clamp/`](clamp/) directory is a fork of [ml-jku/clamp](https://github.com/ml-jku/clamp) that includes our adaptation to run this refitting:

- every PubChem18 compound occurring in any split of the 25 benchmark datasets is removed from the pretraining data, matched on standardized InChI and InChIKey (`clamp/clamp/dataset/overlap_benchmark.py`);
- an independent exact-identity check (InChIKey and canonical SMILES) must find no benchmark molecule before training starts (`clamp/clamp/dataset/check_benchmark_leaks.py`);
- [`clamp/retrain_clamp_noleak.sh`](clamp/retrain_clamp_noleak.sh) runs the whole procedure (data download, featurization, filtering, pretraining from scratch) and [`clamp/validate_clamp_retrain.sh`](clamp/validate_clamp_retrain.sh) validates it.

The refitted weights are available on Hugging Face at [scikit-fingerprints/benchmarking_models_clamp_refitted](https://huggingface.co/scikit-fingerprints/benchmarking_models_clamp_refitted); the benchmark downloads them automatically and runs them as `CLAMP_refitted` (`config/model/clamp_refitted.yaml`).

Unlike the rest of the repository (MIT), `clamp/` is licensed under GPL-3.0, like the original CLAMP, and our modifications in it are shared under the same license (see [License](#license)).

## Testing your own model

To test your own model, please implement a wrapper following the [instructions here](docs/custom_model.md). You can also refer to the existing implementations under `model_wrappers` directory.

For a minimal development smoke test (BBBP only, temporary SQLite DB), see [`AGENTS.md`](AGENTS.md).

If you want to only test your own model, we recommend using the `lightweight` branch, which only contains the benchmarking procedure source code, without any models. You can use our results as a reference point, just copy-and-paste `results/arxiv_preprint_2025_08.db` file to `data/meta.db` to append your results to the existing ones.

### Sharing your model

If you want your model to be included in our latest benchmark, feel free to open a PR with your implementation. We will be happy to review it and include it in the results.

## Tips on controlling number of threads

This project relies on Hydra multirun to sweep datasets (and often model variants). Embedding and scoring both use `hydra.mode: MULTIRUN` by default (see `config/embed.yaml` and `config/score.yaml`). Jobs run serially unless you override the launcher to `joblib` and set `hydra.launcher.n_jobs` (in the experiment config or on the CLI; see [fingerprints](config/experiment/fingerprints.yaml)). Docs: [multi-run](https://hydra.cc/docs/tutorials/basic/running_your_app/multi-run/), [joblib launcher](https://hydra.cc/docs/plugins/joblib_launcher/).

Scoring procedure can also be run in multirun mode, in a similar manner. The default configuration provides 8 datasets in parallel. Additionally, the scikit-learn classifiers will also utilize multithreading, by default using `n_jobs=32`. This is defined in [src/eval/supervised/const.py](src/eval/supervised/const.py).

Some datasets are very large, and for those cases the memory_weight parameter can be used to control the memory usage. This was included due to the OOM issues for larger datasets with high parallelization. If `memory_weight` value is set, the number of `n_jobs` will be divided by `memory_weight` (rounded down). For `n_jobs=8` and `memory_weight=2`, the actual number of jobs will be 4. See [molmuv](config/dataset/clf_ogbg-molmuv.yaml) for an example of `memory_weight` usage.
